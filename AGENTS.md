# AGENTS.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Embed HTML is an Obsidian plugin that adds support for embedding HTML files (`htm`, `html`, `shtml`, `xht`, `xhtml`) in notes and opening them in a dedicated file view. It is built on `obsidian-dev-utils`.

## Architecture

- **Root config files** are thin re-exports — actual logic lives in `scripts/` (`eslint.config.mts` → `scripts/eslint-config.ts`, etc.).
- **`src/`** — plugin source:
  - `main.ts` — Obsidian entry point (default export of `Plugin`)
  - `plugin.ts` — `Plugin` extends `PluginBase`; in `onloadImpl` wires up the settings component, settings tab, the embed registry component, the file view component, and the open-in-new-tab component
  - `html-extensions.ts` — `HtmlExtensions.list()` returns the supported HTML file extensions
  - `html-embed-component.ts` — `HtmlEmbedComponent` (implements `EmbedComponent`); renders an HTML file into a sandboxed `<iframe>` via `srcdoc` (injected `<base>` + `enhance.js`), and supports `#id` subpath `scroll`/`extract` modes. The `<base>` is PREPENDED (`head.createEl('base', { prepend: true })`): a `<base>` only governs the elements that FOLLOW it, so appending it left every relative `<link>`/`<script>`/`<img>` earlier in `<head>` resolving against `app://obsidian.md/` and 404-ing. Stylesheets are then inlined (see `document-stylesheet-inliner.ts`) before the markup reaches `srcdoc`, and again on the LIVE document in `initIframe()`, where a `MutationObserver` (from the framed document's own realm, mirroring `configureMeasurement()`) re-runs the pass for `<link>` elements a script adds later — narrowed to `<link>` additions and `href`/`rel` changes so the `<style>` elements the pass inserts cannot retrigger it. `srcdoc` (rather than an object-URL `src`) is deliberate: reading-view virtualization detaches and re-attaches each embed's DOM on scroll, and re-attaching an iframe reloads it from its source — a revoked single-use object URL would reload to a blank chrome-error page (covered by `scroll-rerender.cross-platform.integration.test.ts`). Sizing: `resolveSize()` merges the parsed `alt` token (see `size-spec.ts`), the `width`/`height` attributes, and the settings defaults into six CSS box properties applied via `setCssProps`; content-keyword axes (`min-content`/`max-content`/`fit-content`) are measured live by a `ResizeObserver` (`measure()` — collapses the iframe to `0px` inside a temporarily-expanded container to read true content size; for content-width it injects a `body { width: <keyword> }` style). Color scheme: `applyColorScheme()` sets the iframe element's CSS `color-scheme` to `dark`/`light` from `app.isDarkMode()` (Chromium propagates the embedding element's `color-scheme` into the framed document, so its `prefers-color-scheme` follows Obsidian's base scheme rather than the OS); applied on load and re-applied on the workspace `css-change` event (registered in `onload()`), so live theme switches reach already-rendered embeds. Verified by `color-scheme.cross-platform.integration.test.ts` (desktop + android). Open in external browser: when `shouldShowOpenInExternalBrowserButton` is on, a `ButtonComponent` is rendered on the container ALONGSIDE the iframe (not in place of it) and hands `buildFileUrl(fullPath)` to `window.open(url, '_external')` — the `_external` target is what routes the URL to the SYSTEM browser instead of an in-app window, and it avoids a desktop-only Electron `shell` import. Gated on `app.vault.adapter instanceof FileSystemAdapter`, which is a DESKTOP test rather than a path-availability one: mobile's `CapacitorAdapter` yields a full path too, but Obsidian exposes no way to hand a local file to a browser there. The URL carries NO fragment, so the `#id` `scroll`/`extract` modes do not travel with it — they are this component's own work on the embedded document, and a browser receives only the plain file (documented in the README and demo note 11). Verified by `open-in-external-browser.desktop.integration.test.ts`
  - `css-inliner.ts` — `inlineCssAsync({ css, cssUrl, readTextAsync })` (pure apart from the injected reader); prepares a stylesheet's TEXT for inlining. Rewrites relative `url()` targets to absolute URLs against the STYLESHEET's own location (not the document's — they differ as soon as the CSS lives in its own folder) and inlines `@import`s recursively, cycle-guarded by a visited-URL set, re-applying each import's `layer(…)` / `supports(…)` / media condition as a wrapping at-rule. An unreadable import is kept (absolutized) rather than dropped
  - `document-stylesheet-inliner.ts` — `inlineDocumentStylesheetsAsync({ baseUrl, doc, readTextAsync })`; swaps every `<link rel="stylesheet">` for an inline `<style>` (created in `head`, then MOVED to the link's exact position by `replaceWith` so the cascade order survives), carrying the `media` attribute over and recording the source in `data-embed-html-inlined-from`; also inlines `@import`s inside existing `<style>` elements. Idempotent, so it can be re-run on the live document. **Why this exists:** a `srcdoc` iframe inherits its parent's policy container AND origin, so Obsidian's `style-src 'unsafe-inline' 'self' https://fonts.googleapis.com` applies inside the embed with `'self'` = `app://obsidian.md`; the vault's resource host is `app://<per-session-hash>`, a DIFFERENT origin, so a linked stylesheet is fetched with `200`/`text/css` and then never applied (`cssRules` throws). Inline `<style>` is permitted, hence inlining. Stylesheets are the ONLY blocked category — the policy sets no `default-src`, so scripts (local and remote), images, fonts, media and `fetch` load unrestricted. Verified end-to-end by `stylesheet-loading.cross-platform.integration.test.ts` and `remote-stylesheet-loading.desktop.integration.test.ts`
  - `stylesheet-reader.ts` — `readStylesheetTextAsync(url)`; reads a stylesheet in Obsidian's context, which is what makes the inlining possible: `requestUrl` for `http(s)` (not CORS-bound, unlike a fetch from the embedded document) and `activeWindow.fetch` for everything else (`app://`, `capacitor://`, `data:`, `blob:` — schemes `requestUrl` cannot serve). Returns `null` on any failure, so an unreachable stylesheet leaves the author's `<link>` in place instead of breaking the render
  - `size-spec.ts` — `parseSizeSpec(token)` (pure, deterministic) turns the container's `alt` token into a `SizeSpec`. Obsidian only routes pure-digit `N`/`NxM` tokens into `width`/`height` attributes; every other token lands verbatim in `alt`. Accepts a full CSS-declaration form (`width: …; min-height: …`) and short forms (`WxH`, `W`, `xH`, `-` → `fit-content`). Value validation is deferred to apply-time (browser CSSOM), keeping the parser jsdom/Chromium-agnostic
  - `html-embed-registry-component.ts` — `HtmlEmbedRegistryComponent`; registers/unregisters the HTML extensions with `app.embedRegistry` so `![[file.html]]` embeds work
  - `html-file-view.ts` — `HtmlFileView` extends `FileView`; opens an HTML file in its own leaf, hosting an `HtmlEmbedComponent` and forwarding ephemeral subpath state
  - `html-file-view-component.ts` — `HtmlFileViewComponent`; registers the file extensions and the `HtmlFileView` view type via injected `ExtensionsRegistrar`/`ViewRegistrar`
  - `open-in-new-tab-component.ts` — `OpenInNewTabComponent` extends `MonkeyAroundComponent` (G65); when `shouldOpenInNewTab` is on, monkey-patches `WorkspaceLeaf.prototype.openFile` so opening an HTML file (matched by extension via `HtmlExtensions`) into an already-occupied leaf is redirected to a fresh `getLeaf('tab')`. Keys the redirect off `openFile` (NOT `setViewState`) because switching between two files of the same `html-file-view` type never calls `setViewState`; gates on the target leaf's view state not being `'empty'` so the first HTML open reuses the current empty tab and layout restore (which uses `setViewState`, not `openFile`) never spawns phantom tabs; guarded against recursion by an `isRedirecting` flag
  - `plugin-settings.ts` — `PluginSettings` data class; six CSS sizing defaults (`defaultWidth`, `defaultHeight`, `defaultMinWidth`, `defaultMaxWidth`, `defaultMinHeight`, `defaultMaxHeight`; min/max default to `''` = unset), three CSS decoration defaults (`border`, `borderRadius`, `background`, all `''` = none) plus the booleans `shouldOpenInNewTab` (default `false`) and `shouldShowOpenInExternalBrowserButton` (default `true`)
  - `plugin-settings-component.ts` — `PluginSettingsComponent` extends `PluginSettingsComponentBase<PluginSettings>`
  - `plugin-settings-tab.ts` — `PluginSettingsTab` extends `PluginSettingsTabBase<PluginSettings>`; renders the six sizing settings in two `SettingGroupEx` groups (Width / Height), the three decoration settings in an Appearance group, and the `shouldOpenInNewTab` / `shouldShowOpenInExternalBrowserButton` toggles in a fourth (Behavior) group. CSS keywords in descriptions use `appendCodeBlock` (dev-utils) so the `obsidianmd/ui/sentence-case` rule does not flag them. The text-binding helper's `propertyName` is narrowed to the string-valued setting keys (`SizeSettingKey`) so the boolean key does not widen it
- **`main` field** points to `src/main.ts` (Obsidian plugin source entry; built artifact is `dist/build/main.js`, not published to npm).
